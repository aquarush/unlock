# Unlock on XO

Unlock's purchase flow migrated to an [XO](https://stack.xo.cash/) template, for the BCH BLAZE 2026
**Migrate to XO** and **Build with XO** bounties.

- **Original project:** [Unlock](https://github.com/aquarush/unlock) (live: https://unlock-bch.pages.dev).
  Sellers turn a secret, link or file into a payment link. Buyers pay in BCH and the server reveals the content.
- **XO implementation:** this folder. The template is in [`template/unlock.template.json`](template/unlock.template.json).

## What was migrated

In the original app, the buyer's wallet builds one transaction that the server checks in
[`src/server/verify.ts`](../src/server/verify.ts):

| Output | Original Unlock | XO template |
|---|---|---|
| 0 | price to the seller's address | `sellerPaymentOutput`, locked to the template's `sellerLockingScript` (seller key generated by XO) |
| 1 | 3% receipt fee (min 2,000 sats) to the minter | `receiptFeeOutput`, locked to `$(<feeLockingScript>)` |
| 2 | `OP_RETURN "UNLK" <item id> <checkout nonce>` | `unlockTagOutput`: `OP_RETURN <"UNLK"> <itemId> <quoteNonce>` |
| 3 | change | added by the engine (`addChangeToInvitation`) |

In XO this becomes a two-party invitation on the action **`sell`**:

- **seller** starts it: generates `sellerKey` and sets `itemId`, `priceSatoshis`, `feeSatoshis` and `feeLockingScript`.
  The seller then adds the payment and fee outputs.
- **buyer** accepts it: provides `quoteNonce` (the secret nonce from their Unlock checkout), adds the tag output,
  funds it from their own coins, adds change, signs and broadcasts.

**Follow-up action:** the seller's payment output is locked to `sellerLockingScript`. That script offers the
**`withdraw`** action to the seller role, which spends the sale output with the template's own unlocking script.

The original UX is not copied. The functionality is the same, and the result is proven: the transaction built by
XO passes the **original Unlock server's `verifyPayment`**, and the same transaction with a wrong nonce is rejected
(`scripts/verify-with-unlock.ts`).

## Inspect with the XO debug tool

1. Open https://blaze.xo.cash and select a **Chipnet** account.
2. **Import Template:** paste `template/unlock.template.json`.
3. **Join Invitation:** paste `invitations/ibUS4RXvCq.purchase.json` (or the withdraw invitation), then **View invitation**.
   Don't click *Accept invitation*.

## Reproduce

Requires Node 22+.

```bash
cd xo && npm install
node scripts/address.mjs buyer          # prints a chipnet address: fund it at https://chipnet.bch.ninja (10k+ sats)
node scripts/sell.mjs ibUS4RXvCq 1000   # seller: creates the invitation -> invitations/ibUS4RXvCq.sell.json
node scripts/buy.mjs ibUS4RXvCq         # buyer: accepts, funds, signs, broadcasts -> invitations/ibUS4RXvCq.purchase.json
                                        #   (DRY=1 builds and signs without broadcasting; optional 2nd arg = checkout nonce)
node scripts/withdraw.mjs <bchtest:address>   # seller follow-up: withdraws the sale
node scripts/release.mjs buyer          # if a run fails: archives open invitations so their coins are released
```

The seller and buyer are separate XO accounts, run in separate processes, and exchange the invitation as a JSON file.
Their mnemonics are created on first run in `.wallets.json` and their engine databases are in `.xo-data/`
(both gitignored). `sell.mjs` sends the receipt fee to the minter key in `../.env.chipnet`; change that line to use your own.

Check a purchase with the original Unlock verifier (from the repo root):

```bash
set -a; . ./.env.chipnet; set +a
npx tsx --conditions=react-server xo/scripts/verify-with-unlock.ts <txid> <itemId> <nonce> <priceSats> <feeSats>
```
